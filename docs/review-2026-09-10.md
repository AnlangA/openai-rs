# Project review and fix record (2026-09-10)

This round confirmed and fixed nine categories of code or build issues and corrected one fuzz-target count in the documentation. The Git working tree was clean at the start of the review; the changes remained in the working tree at the time of this record.

## Scope and method

The review covered workspace configuration, MSRV, feature boundaries, development checks, and pinned specification provenance. Manual inspection focused on authentication and refresh, HTTP/upload/download retries and timeouts, SSE and streamed results, polling, type infrastructure and Structured Outputs, webhook verification, RMCP tool calls, and Codex JSONL request lifecycles and JWT validation. Resource DTOs and endpoint coverage were assessed using existing unit, contract, and compile-isolation tests together with `xtask check`.

This record does not claim a line-by-line review of every source file or prove that no other defects exist. API semantics were evaluated against the repository's pinned specification and the [OpenAI streaming response documentation](https://developers.openai.com/api/docs/guides/streaming-responses). Neither the pinned specification nor dependency versions were upgraded.

## Fixed issues

### 1. A stalled external token provider permanently occupied shared refresh state

- Location: `crates/openai-rs-client/src/workload_identity.rs`, `spawn_refresh`.
- Trigger: with `workload-identity` enabled, a `SubjectTokenProvider` future remains pending indefinitely.
- Cause: the HTTP token exchange had a timeout, but invoking the provider was outside that timeout. Refresh ran in an independent task, so cancelling the outer request did not release shared `refreshing` state.
- Impact: subsequent requests sharing the authentication instance waited for a refresh that could never finish.
- Fix: bound the entire refresh, including the provider, exchange, and response read. Timeout also passes through `finish_refresh` to clear state and wake waiters.
- Regression: `stalled_subject_provider_releases_the_refresh_slot` verifies that a stalled first provider call terminates and a second call can restore authentication.

### 2. Request and handshake timeouts excluded authentication waits

- Locations: `auth.rs`, `transport.rs`, `multipart.rs`, `realtime.rs`, `responses_websocket.rs`, and `beta_responses.rs`.
- Trigger: the authentication cache is empty, a token needs refreshing, or `with_request_timeout` derives a client with a shorter budget.
- Cause: some paths computed remaining time before an unbounded authentication wait; others started the request timer only after authentication finished.
- Impact: total duration exceeded the configured budget or the request never returned. HTTP requests could also use a stale remaining timeout.
- Fix: consistently use `authorization_with_budget`, wait for authentication within the remaining budget, and recompute the time left afterward. Coverage includes JSON, replayable and one-shot uploads, downloads, raw media responses, and three WebSocket handshake paths. Replayable multipart form rebuilding is also budgeted.
- Regression: `request_budgets_bound_pending_authentication_in_every_http_lane` covers five HTTP paths, verifies failure within a derived client's 30 ms budget, and confirms that no API request was sent.

### 3. Cancellation and timeouts did not interrupt a blocked RMCP enqueue

- Location: `crates/openai-rs-rmcp/src/executor.rs`, `call_cancellable`.
- Trigger: the bounded rmcp peer request queue is full.
- Cause: `send_cancellable_request(...).await` ran outside the cancellation/timeout `select!`; the old timeout covered only the response phase after obtaining a request handle.
- Impact: calls configured with `ExecutionControl` could still wait indefinitely during enqueue.
- Fix: race enqueue against cancellation and the deadline. Reuse the same timer during the response phase instead of granting another full budget. Cancellation notifications after handle acquisition remain bounded.
- Regression: `cancellation_interrupts_a_full_request_queue` fills a real rmcp queue and verifies immediate cancellation. The test disables Tokio's cooperative polling budget to avoid mistaking a scheduler yield for a full queue.

### 4. Chained `$ref` references silently lost schema constraints

- Location: `crates/openai-rs-types/src/structured.rs`, `normalize`.
- Trigger: a field has `$ref` plus siblings such as `description`, and the referenced definition is itself another `$ref`.
- Cause: inlining unconditionally deleted the target definition's `$ref`.
- Impact: in `field -> Alias -> Actual`, constraints such as `Actual`'s `type` and `enum` disappeared, changing function-argument or Structured Outputs schemas. Pure alias cycles could also be truncated accidentally.
- Fix: retain the target's next reference so normalization can resolve it, preserving cycle detection, the expansion budget, and the field's own description precedence.
- Regressions: `sibling_ref_follows_aliases_without_losing_constraints` and `sibling_ref_rejects_an_alias_cycle`.

### 5. `#/` was incorrectly treated as the document root

- Locations: reference classification and `resolve_ref` in `structured.rs`; historical decision D0230.
- Cause: code and old tests treated both `#` and `#/` as the root. Under [RFC 6901 section 6](https://www.rfc-editor.org/rfc/rfc6901#section-6), `#` selects the root and `#/` selects its property with an empty-string name.
- Impact: valid references to empty property names were rejected with misleading errors, while invalid bare local references could pass validation.
- Fix: resolve empty property names correctly; return `UnresolvableRef` for missing targets; validate resolvability for bare local references too. D0230 now includes an explicit correction.
- Regressions: `slash_pointer_resolves_the_empty_property_name` and `missing_empty_property_reference_is_unresolvable_in_both_forms`, retaining the existing root-reference policy at that time.

### 6. Polling mixed system and Tokio clocks

- Location: `crates/openai-rs-client/src/poll.rs`, `poll_until`.
- Cause: deadlines used `std::time::Instant`, while waiting used Tokio timers.
- Impact: pausing or advancing the Tokio clock advanced waits without advancing the deadline. Several paused-clock tests ran for minutes and accumulated many poll records.
- Fix: use `tokio::time::Instant` consistently for polling.
- Regression: `polling_deadline_uses_the_runtime_clock` verifies that a 30 ms budget ends after exactly 30 ms of simulated time. Existing server-interval and explicit-interval tests continue to cover pacing.

### 7. Dropping a Codex request future leaked resources and JSONL framing state

- Location: `crates/openai-rs-codex/src/app_server/client.rs`.
- Trigger: an outer `timeout`, `select!`, or task cancellation drops a request while it waits to write or receive a response.
- Cause: pending-table and semaphore-permit cleanup existed only on normal returns and SDK-owned timeout paths. Cancellation of `write_all` also lacked a shared connection guard.
- Impact: unanswered requests permanently occupied concurrency slots. Reusing a connection after a partially written JSONL frame could corrupt framing.
- Fix: use a drop guard to remove pending entries. Cancellation after writing starts immediately prevents reuse and schedules connection cleanup; cancellation before acquiring the write lock only releases the slot. Separate the closed state from the cleanup-started state so early closure does not skip cleanup. Internal write timeouts still return `WriteTimeout`.
- Regressions: `dropped_request_releases_its_pending_slot` checks capacity recovery after dropping a real request future; `cancelled_write_blocks_reuse_and_completes_shutdown` checks immediate reuse prevention and asynchronous cleanup.

### 8. Platform-specific test code blocked all-feature Clippy on Windows

- Locations: test modules in Codex `runtime.rs` and `app_server/client.rs`.
- Cause: tests had Unix or macOS/arm64 conditions, but their imports and `fake_runtime` helper lacked matching conditions.
- Impact: Windows builds emitted unused-import/dead-code warnings, which the required `-D warnings` check rejected.
- Fix: apply matching conditional compilation to the imports and helpers while retaining cross-platform tests.
- Verification: workspace/all-targets/all-features Clippy on Windows with Rust 1.88.0.

### 9. Git line-ending conversion broke pinned byte-for-byte artifacts

- Locations: new `.gitattributes`, `spec/upstream`, and `spec/contracts/*.json`.
- Trigger: Windows checkouts with `core.autocrlf=true`.
- Evidence: the OpenAPI file grew from 3,405,126 to 3,490,490 bytes; its SHA-256 changed from `5be8cde8...` to `8404f0a3...`, causing `xtask check` to fail.
- Cause: the repository did not constrain line-ending conversion for files verified by exact bytes.
- Fix: disable text conversion for upstream snapshots and require LF for generated JSON projections. Original bytes were restored from Git objects without changing schema content or weakening hash checks.
- Verification: `xtask check` passed for both upstream sources and all five generated projections.

Additionally, `docs/development.md` now lists four fuzz targets rather than three, including the existing `responses_input_item` target.
