# API documentation review: fix record

This record covers the four findings in the [API documentation review](api-review-2026-09-10.md).

| Finding | Implemented fix | Regression coverage |
|---|---|---|
| FunctionTool discarded the asynchronous flag | Added `asynchronous(bool)` and `is_async()`; preserve optional `async` booleans and unknown fields | True, false, omission, null, namespace round trips, and actual POST bodies |
| Valid recursive schemas were rejected | Preserve root and local recursive references; use a single-branch anyOf for siblings on recursive edges while retaining alias validation and the expansion budget | Official tree schema, mutual recursion, recursive schemars types, idempotence, invalid aliases, and expansion limits |
| An excessive Retry-After caused premature retries | JSON, Administration, and multipart share server-delay parsing; return an API error with metadata when a valid delay exceeds the policy limit | 429/503 across JSON, upload, download, media JSON, and Administration; invalid hints and valid short waits |
| Safety alert details could not be retrieved | Added `client.safety().alerts().retrieve(id)` with Platform project authentication, a typed response, and facade exports | Null and unknown fields, required fields, path encoding, headers, bodyless requests, and 404 metadata |

## Usage

```rust
let tool = FunctionTool::new("lookup").asynchronous(true);

// Use data.id from a verified webhook, rather than the webhook event's own id.
let alert = client.safety().alerts().retrieve("alert_...").await?;
let affected_request_id = alert.body().request_id();
let retrieval_request_id = alert.meta().request_id();
```

`request_paused` means the server successfully registered a state that prevents execution; it does not prove execution has already stopped. `reason` retains required-nullable semantics and accepts an explicit null.

## Contracts and scope

- Decisions D0288-D0291 record sources, behavior changes, and tests.
- The new Safety API is registered under `documented_operations` in `implementation.toml`, checked by xtask, and projected into `operations.json`. Its entry contains an official documentation URL and captured-content hash, separately from the frozen OpenAPI operation count.
- The upstream OpenAPI snapshot, dependency versions, and MSRV were unchanged.
- The default automatic-wait limit remains 120 seconds. Delays above that limit no longer fall back to a shorter local backoff.
- Two families of timing tests expected Windows to complete initial network I/O within 40-50 ms and occasionally failed in the full suite. They now synchronize on the request or connection starting before advancing Tokio's simulated clock. Existing state and retry-count assertions remain.
- Cache diagnostics, steering, configuration_update, and other items classified as supported through extension fields with room for stronger types were outside these four fixes.
