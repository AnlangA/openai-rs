# API 文档审查问题修复记录

本记录对应 [API 文档对照审查](api-review-2026-09-10.md) 中的四项发现。

| 问题 | 完成的修复 | 回归验证 |
|---|---|---|
| FunctionTool 丢弃异步标记 | 新增 `asynchronous(bool)`、`is_async()`，保留可省略的 `async` 布尔值及未知字段 | true/false/省略/null、namespace 往返、实际 POST 请求体 |
| 合法递归 schema 被拒绝 | 保留根递归和局部递归引用；递归边上的同级字段用单分支 anyOf 隔开，继续保留别名检查和展开预算 | 官方树结构、相互递归、schemars 递归类型、幂等性、无效别名和展开上限 |
| 超过上限的 Retry-After 导致过早重试 | JSON、Administration、multipart 共用服务端延迟解析；有效等待值超过策略上限时返回保留元数据的 API 错误 | 429/503；JSON、上传、下载、媒体 JSON、Administration；无效提示和合法短等待 |
| 无法检索安全告警详情 | 新增 `client.safety().alerts().retrieve(id)`，Platform 项目认证，类型化响应和 facade 导出 | 空值与未知字段、必填字段、路径编码、请求头、无请求体、404 元数据 |

## 使用方式

```rust
let tool = FunctionTool::new("lookup").asynchronous(true);

// 使用已验证 webhook 的 data.id，而不是 webhook 事件本身的 id。
let alert = client.safety().alerts().retrieve("alert_...").await?;
let affected_request_id = alert.body().request_id();
let retrieval_request_id = alert.meta().request_id();
```

`request_paused` 表示服务端成功注册了阻止执行的状态，不能据此断言已经停止执行。`reason` 保留 required-nullable 语义，返回 null 时仍可正常解码。

## 契约与范围

- 决定记录 D0288–D0291 说明来源、行为变化和测试。
- 新 Safety API 位于 `implementation.toml` 的 `documented_operations`，由 xtask 校验并投影到 `operations.json`。条目附有官方文档 URL 和捕获内容哈希，独立于原有固定 OpenAPI 的操作计数。
- 上游 OpenAPI 文件和版本未改动，依赖版本及 MSRV 未提高。
- 默认自动等待上限仍为 120 秒；超出上限时不再以短退避替代服务端最短等待。
- 原先两个类别的计时测试依赖 Windows 在 40–50ms 内完成首次网络 I/O，整套测试中出现偶发失败。现先同步确认请求/连接已开始，再推进 Tokio 模拟时间；原有状态及重试次数断言保留。
- 缓存诊断、steering、configuration_update 等报告中标记为“可透传、可完善类型”的条目，不属于本轮四项修复范围。
